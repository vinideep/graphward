# Event: Feature Added
<!-- freshness: last_checked=2026-07-13 -->

Trigger: a new skill, agent, workflow, gate, or CLI command is added to the package.

## New Skill

1. Create `templates/canonical/skills/<name>/SKILL.md`.
2. Add `<name>` to `SKILL_NAMES` in `src/templates.ts:14-57`.
3. Add an entry to `SKILL_CATALOG` in `src/visualizer/index.ts` (not automatically enforced — see `12-technical-debt.md`; do this manually every time).
4. If any workflow or `validateCanonicalTemplates()` should require specific phrases/contracts from the new skill, add checks in `src/templates.ts:108-273`.
5. Consider adding the skill to `WORKFLOW-ROUTING.md`'s per-command routing table (rendered content, not source — check how routing tables are generated in `token-optimizer.ts`).
6. Update `SKILLS-INDEX.md` generation coverage (auto-generated by `generateSkillsIndex`, should pick up the new skill automatically if `SKILL_NAMES` is updated correctly).
7. Add/extend `templates.test.mjs` coverage.

## New Agent

1. Create `templates/canonical/agents/<name>.md` with the expected frontmatter (`name`, `description`).
2. Add `<name>` to `AGENT_NAMES` in `src/templates.ts:59-75`.
3. Add an entry to `AGENT_METADATA` in `src/adapters/index.ts:229-295` (context paths, skills list, autoRoute/parallel flags) — required for `agentsAsJsonAt()` to render a correct `agent.json` manifest.
4. Update `.claude/agents/` documentation/list mentions if user-facing docs (e.g. README.md) enumerate agents.

## New Workflow (slash command)

1. Create `templates/canonical/workflows/<name>.md`.
2. Add `<name>` to `WORKFLOW_NAMES` in `src/templates.ts:77-89`.
3. If the workflow takes user input, add it to `INPUT_WORKFLOWS` and `WORKFLOW_ARGUMENT_HINTS` in `src/adapters/index.ts:18-40`.
4. If the workflow must state it "does not modify product code" (read-only workflows), ensure that exact phrase appears — `validateCanonicalTemplates()` checks for it on a specific list of workflow names (src/templates.ts:151-164).
5. Add the new workflow to the `workflowDescriptions` record for Gemini CLI rendering (src/adapters/index.ts:438-450) — missed entries here produce an empty description in `.gemini/commands/*.toml`.

## New Safety Gate

1. Create `src/gates/<name>.ts` exporting an async function returning `GateResult`.
2. Add `<name>` to `GATE_NAMES` in `src/gates/index.ts:48-49` and a `case` in `runGate()`'s switch (src/gates/index.ts:146-153).
3. Add the gate name to the MCP `run_gate` tool's `inputSchema.gate.enum` (src/mcp/index.ts:67-68) and the CLI `usage()` text (src/cli/index.ts:77).
4. Add coverage in `gates.test.mjs`.
5. Document detection heuristics and known conservative-bias in `11-complex-areas.md`.

## New CLI Command / MCP Tool

See `events/api-changed.md`.

## Cross-Cutting Step For Any New Feature

Re-run `npm test && npm run test:integration` before considering the feature complete — `templates.test.mjs` and `install-integration.test.mjs` catch most cross-registration mistakes (forgetting to add a name to one of the constant lists) automatically.
